# Explain Again: instructions for agents

A Claude Code mod (a plugin of function hooks), owned by smughead. README.md says what it does; docs/decisions.md says why it looks the way it does and what the platform cannot do. Read both before changing behavior or visuals.

## Working with the owner

- The owner is a product manager, not an engineer. Explain changes by what the user sees and why it matters, in plain language.
- Ask before changing behavior or visuals that docs/decisions.md records as decided.
- Pushes to GitHub are deliberate: commit as you go, push only when the owner asks.

## Design rules

- Keep the first view minimal: one button per format, no extra icons, no tooltips, nothing that resizes or shifts on hover. Secondary choices go behind a click (the swap-in-place row).
- Use the app's own button styles: a non-plain `Button` is the app's bordered button, `variant="primary"` the filled one. Never wrap a `plain` Button in a bordered `Box` to suggest a larger click area: on desktop only the text responds.
- No em dashes in anything the end user sees (buttons, requests, command output). Requests should read like something the person would type.

## Checks before handing over any change

- `claude plugin validate ./.claude-plugin/plugin.json` (the mod), `claude plugin validate .` (the install file) and `claude plugin test .` must all pass. Its warning that CLAUDE.md is not shipped as plugin context is expected: CLAUDE.md is for agents working in this repository. A drawing the app refuses renders nothing at all, silently; the render tests are what catch that.
- Use the Claude Code CLI bundled with the desktop app: `~/Library/Application Support/Claude/claude-code/<version>/<hash>/claude.app/Contents/MacOS/claude`. The `claude` on PATH may be too old for mods.
- The owner's sessions load the mod from this folder (`CLAUDE_CODE_PLUGIN_DIRS` in `~/.claude/settings.json`), and every tool shell inherits that setting, so a test run of `claude` loads it too. For an isolated test, such as an install from GitHub, run with `env -u CLAUDE_CODE_PLUGIN_DIRS` and `CLAUDE_CONFIG_DIR` set to a temporary folder.
- Agents cannot screenshot the Claude app. Visual checks come from the owner: ask for one specific check at a time.
- Before asking for a live check, confirm the session runs the current code. A desktop app session loads the mod once at start and reloads it only if `CLAUDE_CODE_PLUGIN_DIR_WATCH=1` was set when it started (check `env` in a shell). Otherwise the check needs a new session.

## Layout

- `.claude-plugin/plugin.json`: the manifest. `.claude-plugin/marketplace.json`: lets `claude plugin marketplace add` install from this repository.
- `hooks/register.tsx`: the mod. `types/index.d.ts`: the contract for its session state. `tests/`: render and behavior tests.
- `.claude-plugin/types/` is generated by Claude Code when the plugin loads (the root `tsconfig.json` extends it). It is not committed.
